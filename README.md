# Warehouse Simulator

倉庫管理 + 2Dレイアウト作成 + 物流シミュレーションのWebアプリケーション。
実際の倉庫を2Dマップ上に再現し、**入庫 → 保管場所決定 → フォークリフト搬送 → 出荷完了**
までの動きを画面上で検証できる「倉庫のデジタルツイン」を目指しています。

現在の実装状況: **Phase 1（2D倉庫エディタ）完了 + 経路探索エンジンの基盤実装済み**

---

## 1. 技術構成

| 領域 | 採用技術 | 選定理由 |
| --- | --- | --- |
| フロントエンド | React 18 + TypeScript + Vite | 型安全・高速なHMR |
| 2D描画 | Konva.js (react-konva) | 図形の選択/変形/ドラッグが標準装備。CAD的な編集に向く |
| 状態管理 | Zustand | ボイラープレートが少なく、Undo/Redoなどを素直に書ける |
| バックエンド | Node.js + TypeScript + Express | フロントと同一言語でドメインモデルを共有できる |
| データベース | SQLite (`node:sqlite`) | Node標準機能のためネイティブビルド不要。標準SQLのみ使用しPostgreSQL移行に備える |
| 経路探索 | 自前実装のA* (8方向 + 経路直線化) | 倉庫特有のコスト（歩行者エリア回避・車体クリアランス）を扱うため |
| テスト | Vitest | ドメインロジックとAPIの回帰テスト |

**モノレポ構成（npm workspaces）**にして、ドメインモデルとシミュレーションエンジンを
`@ws/shared` に集約しています。UIから独立しているため、
将来サーバ側でのバッチシミュレーションやレイアウト最適化（Phase 8）にも同じコードを再利用できます。

### 動かし方

```bash
npm install
npm run dev     # http://localhost:5173 （APIは 5178 で起動）
```

```bash
npm run build   # 型チェック + 本番ビルド
npm start       # http://localhost:5178 で API + ビルド済みUIを配信
npm test        # ドメイン + API のテスト (35件)
npm run typecheck
```

データベースは既定で `data/warehouse.db` に作成されます（`DB_FILE` 環境変数で変更可）。

## 2. ディレクトリ構造

```
packages/
├── shared/                     # @ws/shared — UI非依存のドメイン層
│   ├── src/domain/
│   │   ├── types.ts            # 全エンティティの型定義
│   │   ├── objectSpecs.ts      # 配置オブジェクトの種別カタログ（既定サイズ・色・走行可否）
│   │   ├── locations.ts        # ロケーション採番ルールと自動生成
│   │   ├── factories.ts        # 既定値つきのエンティティ生成
│   │   └── sampleWarehouse.ts  # 初期表示用サンプル倉庫
│   ├── src/geometry/           # 座標変換・回転・スナップ・単位換算
│   ├── src/sim/                # シミュレーションエンジン
│   │   ├── navGrid.ts          # 走行可能エリアのラスタ化（障害物膨張・通行コスト）
│   │   ├── astar.ts            # A* 経路探索 + 経路直線化
│   │   └── travel.ts           # 台形速度プロファイル・走行時間・速度超過の計測
│   ├── src/io/                 # CSV パーサ / エクスポータ
│   └── test/                   # ドメインロジックのテスト
│
├── server/                     # @ws/server — REST API
│   ├── src/db/database.ts      # SQLite接続・マイグレーション・トランザクション
│   ├── src/repositories/       # 永続化（SQLはここに閉じ込める）
│   ├── src/routes/             # HTTPエンドポイント
│   └── test/api.test.ts        # API結合テスト
│
└── web/                        # @ws/web — エディタUI
    └── src/
        ├── api/client.ts       # APIクライアント
        ├── store/editorStore.ts# Zustand（編集状態・履歴・ログ）
        ├── canvas/             # Konva描画（グリッド/オブジェクト/ロケーション/経路）
        └── components/         # ツールバー・インスペクタ・ダイアログ・ログ
```

**分離の方針**: 「コンポーネント（web/src/components, canvas）」「データモデル（shared/src/domain）」
「シミュレーションエンジン（shared/src/sim）」を相互に依存させないことで、
Phase 3以降でシミュレーション機能を追加してもUIの改修が最小限で済むようにしています。

## 3. データモデル

```
Warehouse ──┬── Layout ──┬── LayoutObject（ラック/棚/柱/壁/出入口/各種エリア/フォークリフト）
            │            │        └── RackSpec（列数・段数・最大収納数・採番ルール）
            │            ├── Location（ロケーション番号・座標・作業位置・最大収納数）
            │            ├── Inventory ── Product
            │            ├── InboundOrder / OutboundOrder
            │            └── Simulation ──┬── Task ── Path
            │                             └── SimulationEvent
            └── Product（商品マスタ：JAN・サイズ・重量・出荷頻度）
```

| エンティティ | 役割 | 主なフィールド |
| --- | --- | --- |
| `Warehouse` | 倉庫の実寸と表示設定 | 幅/奥行(m)、縮尺(1m=Npx)、グリッド、構内制限速度 |
| `Layout` | 倉庫の「配置案」。A/B比較の単位 | 名称、複製元 |
| `LayoutObject` | マップ上の配置物（種別ごとの合併型） | 座標・サイズ・回転、走行可否 |
| `RackObject` | ラック/棚 | `RackSpec`（列数・段数・ピッキング面・採番ルール） |
| `Location` | ロケーション | 番号、列/段、中心座標、**作業位置**、最大収納数 |
| `Product` | 商品マスタ | サイズ・重量・**出荷頻度**（高/中/低回転） |
| `Inventory` | ロケーション別在庫 | 数量、入庫日、ロット |
| `Forklift` | 車両 | 最大速度・加減速度・最大積載重量・状態・向き |
| `Task` | 作業単位 | 入庫格納/取出、始点・終点、割当車両、所要時間 |
| `Simulation` | 実行設定と結果 | 開始時刻、刻み、制限速度、集計指標 |
| `SimulationEvent` | 時系列ログ | 時刻、種別、車両、ロケーション |

**座標系**: ドメイン層の座標・寸法はすべてメートル。ピクセル変換は表示層のみが行います。
原点は倉庫の左上、回転はKonvaと同じく `(x, y)` を中心とした時計回りです。

`Location.approachX/Y` は「フォークリフトが停車する通路側の作業位置」で、
ラックのピッキング面と回転角から自動計算されます。経路探索はこの点を目的地に使います。

### 永続化

SQLiteに正規化して保存します（`packages/server/src/db/database.ts` のマイグレーション参照）。
ラック仕様・フォークリフト諸元のような可変スキーマ部分のみ `props` にJSONで格納し、
検索対象になる `locations` は完全に正規化しています。
SQLiteの独自構文を使わないため、PostgreSQLへは接続層の差し替えだけで移行できます。

### 操作方法

| 操作 | 方法 |
| --- | --- |
| 配置 | 左パレットをクリック → マップをクリック（またはマップへドラッグ&ドロップ） |
| 選択 | クリック / Shift+クリックで追加 / 空白部分をドラッグで範囲選択 |
| 移動 | ドラッグ、または矢印キー（Shiftで1m単位） |
| 変形 | 選択後にハンドルをドラッグ、または右パネルに数値入力 |
| 回転 | `R`（Shift+Rで逆回転）／ハンドル |
| 複製 / 削除 | `Ctrl+D` / `Delete` |
| Undo / Redo | `Ctrl+Z` / `Ctrl+Shift+Z` |
| 保存 | `Ctrl+S` |
| ズーム / パン | ホイール / スペース+ドラッグ・中ボタンドラッグ |
| ラック再設定 | ラックをダブルクリック |
| 走行ルート確認 | 「経路確認」ツール → 出発点・目的地をクリック |

初回起動時は、北側入庫口・南側出荷口・ラック6本（180ロケーション）・
フォークリフト2台を配置したサンプル倉庫が自動生成されます。

## 6. 将来拡張への備え

- **RFID / バーコード / ハンディ端末 / IoT**: 位置情報は `ForkliftRuntime` に集約しているため、
  実機のトラッキングデータをそのまま流し込めます。
- **CSV/Excelインポート**: `@ws/shared/io` に依存ライブラリなしのCSVパーサを実装済み
  （BOM・CRLF・引用符対応）。商品マスタ・在庫・ロケーションの取込に使用します。
- **PostgreSQL移行**: SQLは `packages/server/src/repositories/` に閉じ込め、標準構文のみ使用。
- **AIレイアウト最適化**: シミュレーションエンジンがUIから独立しているため、
  ヘッドレスで多数のレイアウト案を評価できます。
